# 파일 탐색 및 수정 규칙

## 수정 전 탐색
1. 사용자가 제시한 정확한 문구로 프로젝트 전체를 검색한다.
2. 검색 결과가 없으면 핵심 단어, 한영 표현, URL·경로·메뉴명으로 범위를 넓힌다.
3. 메뉴·라우트·페이지에서 실제 컴포넌트와 데이터 파일까지 추적한다.
4. `git_status`로 기존 수정 중인 파일을 확인한다.
5. 수정 전 관련 파일을 `read_file`로 반드시 읽는다.
6. 충분히 확인한 후에도 위치를 찾지 못할 때 추가 정보를 요청한다.

검색 결과 없음은 해당 기능이 없다는 뜻이 아니다. 런타임 데이터, props, 번역, 조합된 문자열을 고려한다.

## 변경 원칙
- 기존 구조와 코드 스타일을 유지하며 최소 범위를 수정한다.
- 가능하면 `replace_text`로 필요한 부분만 교체한다. 전체 덮어쓰기는 최소화한다.
- 파일 이름 변경 시 참조 경로와 import, 라우트 영향까지 점검한다.
- 기존 사용자의 미커밋 변경을 임의로 덮어쓰지 않는다.
